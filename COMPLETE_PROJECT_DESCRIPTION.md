# Complete Project Description

## 1. Software Description

### 1.1 Project Purpose

This project is firmware for an STM32F303-based impedance measurement PCB. The firmware controls a signal generator, samples analog measurement signals, calculates impedance magnitude and phase, communicates with a computer over USB-UART, and stores measurement results in an external SPI flash memory.

The basic software purpose is:

```text
generate sine sweep -> measure electrode response -> calculate impedance -> send and store results
```

The firmware is written for an STM32CubeIDE / STM32CubeMX style project. The generated HAL initialization code configures the MCU clocks, GPIO, ADC, DMA, SPI, and USART peripherals. User-written modules provide the AD9833 signal generator driver, W25Q32 flash driver, UART command protocol, impedance calculation, and flash logging.

The main firmware files are:

| File | Purpose |
| --- | --- |
| `Core/Src/main.c` | Main application, peripheral initialization, sweep loop, command handlers. |
| `Core/Inc/main.h` | Main exported handles, pin definitions, command function prototypes. |
| `Core/Src/ad9833.c` and `Core/Inc/ad9833.h` | AD9833 waveform generator driver. |
| `Core/Src/impedance.c` and `Core/Inc/impedance.h` | ADC sample processing and impedance calculation. |
| `Core/Src/uart_comm.c` and `Core/Inc/uart_comm.h` | UART receive, command parser, and result output. |
| `Core/Src/w25q32.c` and `Core/Inc/w25q32.h` | Low-level SPI flash driver. |
| `Core/Src/flash_log.c` and `Core/Inc/flash_log.h` | Measurement-record storage layer on top of W25Q32 flash. |

### 1.2 Startup Sequence

When the PCB powers up, the STM32 starts executing `main()`. The first software action is standard HAL startup. The firmware calls `HAL_Init()` and then `SystemClock_Config()`. The system clock is derived from the MCU external clock source and PLL configuration generated by STM32CubeMX.

After clock setup, the firmware initializes the peripherals:

```text
MX_GPIO_Init()
MX_DMA_Init()
MX_ADC1_Init()
MX_SPI1_Init()
MX_USART1_UART_Init()
```

The GPIO initialization sets the chip-select/frame-sync lines for the AD9833 and W25Q32 flash. It also configures the status LED pin. ADC1 is configured for two regular channels. SPI1 is configured as a master bus. USART1 is configured for USB-UART communication through the CP2102 bridge.

After the generated peripheral setup, the application initializes its own modules:

```text
UART_Comm_Init(&huart1)
Imp_Init()
W25Q32_Init(&hspi1)
FlashLog_Init()
AD9833_Init()
```

The UART module arms interrupt-based single-byte reception. The impedance module calibrates/initializes ADC measurement support. The W25Q32 driver stores the SPI handle and prepares the flash chip-select. The flash log module scans any existing measurement log in flash. The AD9833 module resets the waveform generator, sets a default frequency, sets phase to zero, and configures sine-wave output.

Finally, the firmware sends startup messages to the computer:

```text
FLASH,ID,0x...
READY
STATUS,...
```

The `FLASH,ID` line confirms that the firmware read the W25Q32 JEDEC ID. `READY` indicates that initialization completed. `STATUS` reports the current sweep settings, run state, feedback resistor value, and flash record count.

### 1.3 Command-Based Control From the Computer

The computer communicates with the PCB using simple ASCII commands over USB-UART. The physical USB connection goes through the CP2102. On the STM32 side, the firmware sees this as USART1.

The UART receive logic is interrupt based. Each received byte is collected into a buffer until a newline or carriage return arrives. When a full command line is ready, `UART_ProcessCommand()` parses it and calls the corresponding command handler in `main.c`.

The main computer-to-PCB commands are:

| Command | Purpose |
| --- | --- |
| `START` | Starts a measurement sweep. |
| `STOP` | Stops the running sweep. |
| `STATUS` | Requests current state and sweep settings. |
| `SET_START_FREQ,<Hz>` | Sets the sweep start frequency. |
| `SET_STOP_FREQ,<Hz>` | Sets the sweep stop frequency. |
| `SET_STEP_FREQ,<Hz>` | Sets the sweep frequency step. |
| `SET_RF,<ohms>` | Sets the feedback resistor value used in impedance calculation. |
| `FLASH_STATUS` | Requests how many measurement records are stored in flash. |
| `ERASE_FLASH` | Erases the reserved flash log region. |
| `DUMP_FLASH` | Reads stored flash measurement records back to the computer. |

The firmware replies using ASCII status lines:

| Reply | Meaning |
| --- | --- |
| `OK ...` | Command was accepted. |
| `ERROR,...` | Command failed or was invalid. |
| `STATUS,...` | Current run state and configuration. |
| `SWEEP,BEGIN` | Measurement sweep started. |
| `DATA,...` | Live measurement result for one frequency point. |
| `SWEEP,DONE` | Measurement sweep finished. |
| `FLASH_STATUS,...` | Flash log count and capacity. |
| `FLASH_DUMP,BEGIN,...` | Start of stored data readback. |
| `FLASH_DATA,...` | One stored measurement record from flash. |
| `FLASH_DUMP,END` | End of stored data readback. |

The computer controls the process, but the STM32 firmware performs the actual measurement, calculation, flash writing, and flash reading.

### 1.4 Sweep Configuration

The firmware uses configurable sweep parameters. The default values are defined in `main.h`:

```text
SWEEP_START_FREQUENCY = 1000 Hz
SWEEP_STOP_FREQUENCY  = 100000 Hz
SWEEP_STEP_FREQUENCY  = 1000 Hz
SWEEP_DELAY_MS        = 100 ms
```

The user can modify the start frequency, stop frequency, step frequency, and feedback resistor value from the computer. These values can only be changed while a measurement is not running. This avoids changing the sweep definition in the middle of a sweep.

Before starting, `Process_Start_Command()` checks whether the sweep configuration is valid. The start frequency must be greater than zero, the stop frequency must be greater than or equal to the start frequency, the step frequency must be greater than zero, and the feedback resistor value must be positive.

If the configuration is valid, the firmware erases the reserved flash log area by calling `FlashLog_BeginSweep()`. This means the flash stores the newest sweep, not a mixture of old and new data. After flash erase succeeds, `measurement_running` is set and the sweep begins.

### 1.5 Frequency Generation With AD9833

The firmware uses the AD9833 as a direct digital synthesis waveform generator. The AD9833 is controlled over SPI1. The firmware uses the following signals:

```text
SPI1 SCK  -> AD9833 SCLK
SPI1 MOSI -> AD9833 SDATA
PA4       -> AD9833 FSYNC
```

The AD9833 has a 25 MHz master clock from the `ASE-25.000MHZ-LC-T` oscillator. The firmware constant is:

```text
AD9833_MCLK = 25000000UL
```

When the sweep reaches a frequency point, the firmware calls:

```text
AD9833_SetFrequency(freq)
```

Inside the AD9833 driver, the desired frequency is converted into the AD9833 frequency tuning word. The tuning word is split into two 14-bit words and written into the AD9833 frequency register over SPI. The firmware configures sine-wave output, so the AD9833 generates a sine excitation signal at `VOUT`.

This sine signal is applied through the analog front end toward the electrode/load being measured.

### 1.6 ADC Sampling

The STM32 samples two analog channels using ADC1 and DMA:

```text
ADC1_IN1 / PA0 -> reference channel
ADC1_IN2 / PA1 -> signal channel
```

The ADC is configured for two conversions in scan mode. DMA stores the interleaved samples in:

```c
uint16_t adc_buffer[2 * SAMPLE_COUNT];
```

The sample count is:

```text
SAMPLE_COUNT = 256
```

The buffer format is:

```text
adc_buffer[0] = reference sample 0
adc_buffer[1] = signal sample 0
adc_buffer[2] = reference sample 1
adc_buffer[3] = signal sample 1
...
```

During each measurement point, the firmware starts ADC DMA, waits briefly, stops ADC DMA, and then converts raw ADC counts into voltages using:

```text
ADC_VREF = 3.3 V
ADC_MAX  = 4095
```

The converted values are placed into:

```c
ref_samples[SAMPLE_COUNT]
sig_samples[SAMPLE_COUNT]
```

The impedance calculation uses an estimated per-channel-pair sample rate from the current ADC configuration:

```text
ADC clock = 72 MHz
ADC sample time = 61.5 cycles
ADC conversion time = 12.5 cycles
scan channels = 2
effective sample rate = 72 MHz / ((61.5 + 12.5) * 2)
```

### 1.7 Magnitude And Phase Calculation

The impedance-processing code removes the DC mean from the reference and signal arrays. This is important because the useful information is the AC sine component, not the DC offset or bias level.

After DC removal, the firmware calculates a frequency-aware sine/cosine fit for both the reference and signal waveforms. This is similar to synchronous detection at the actual AD9833 excitation frequency. For each sample index, the firmware calculates:

```text
angle = 2 * pi * frequency * sample_index / sample_rate
```

It then solves for the cosine and sine coefficients of the sampled waveform. This avoids the previous assumption that exactly one waveform cycle must fit inside the 256-sample window.

From these sums, the firmware calculates the signal magnitude and the phase of each channel. The phase difference is calculated as:

```text
phaseDeg = phaseSig - phaseRef
```

The result is normalized into the range:

```text
-180 degrees to +180 degrees
```

The current method therefore calculates both:

```text
impedance magnitude
impedance phase
```

The calculation also produces real and imaginary parts:

```text
realPart = magnitude * cos(phase)
imagPart = magnitude * sin(phase)
```

### 1.8 Impedance Calculation Method

The project currently uses a swept-sine impedance measurement method. At each frequency, the AD9833 produces a sinusoidal excitation. The analog front end converts the electrode/load response into measurable voltages. The STM32 compares the measured signal against a reference signal and calculates magnitude and phase.

The firmware then uses the transimpedance relationship:

```text
current_peak = measured_signal / Rf
Z = measured_reference / current_peak
```

The measured reference amplitude comes from the fitted reference-channel waveform, so the firmware no longer assumes a fixed `Vin_peak = 1.0f`. The feedback resistor value `Rf` is configurable from the PC using `SET_RF,<ohms>`.

The result is returned as a `BodePoint`:

```c
typedef struct
{
    float magnitude;
    float phaseDeg;
    float realPart;
    float imagPart;
} BodePoint;
```

This is a Bode-style measurement result: frequency, magnitude, and phase.

One important technical note is that `Process_Impedance(float frequency)` now uses the actual excitation frequency when computing the sine/cosine fit. The calculation depends on the ADC sample-rate estimate matching the real ADC timing. For even better measurement accuracy, a future improvement would be to trigger ADC sampling from a hardware timer so the sample rate is exact and independent of continuous-conversion timing.

### 1.9 Live UART Output

After calculating a result at one frequency, the firmware sends the live measurement to the computer:

```c
UART_SendImpedanceData(freq, result.magnitude, result.phaseDeg);
```

The transmitted live data contains:

```text
frequency
impedance magnitude
phase
```

The magnitude and phase are scaled for text output. This allows a PC GUI, serial terminal, or data-logging script to parse the result line easily.

The live result goes to the computer first. Immediately after that, the same result is written to SPI flash. The data order for each measurement point is:

```text
calculate result -> send result to computer -> write result to flash
```

### 1.10 Flash Storage

The PCB includes a W25Q32JVSSIQ SPI flash memory. The low-level driver in `w25q32.c` supports:

```text
read JEDEC ID
read status
write enable
sector erase
chip erase
page program
read data
```

The newer `flash_log.c` module uses these low-level functions to store measurement records. It reserves a flash region starting at address `0x000000`. At the start of each sweep, this region is erased. Then one fixed-size record is appended for each measured frequency point.

Each flash record contains:

```text
magic marker
record index
frequency in Hz
magnitude
phase in degrees
real part
imaginary part
```

The flash data is written by the STM32 firmware, not by the computer. The computer can only request actions through UART commands. For example, the computer can ask the firmware to erase flash or dump flash data, but the actual SPI flash transaction is always performed by the STM32.

The related UART commands are:

```text
FLASH_STATUS
ERASE_FLASH
DUMP_FLASH
```

`FLASH_STATUS` reports count and capacity. `ERASE_FLASH` clears the reserved log region. `DUMP_FLASH` reads each stored record and sends it to the computer as ASCII text.

### 1.11 Main Runtime Flow

The complete runtime flow is:

```text
1. Boot STM32.
2. Initialize clocks and peripherals.
3. Initialize UART, ADC, SPI, AD9833, W25Q32 flash, and flash log.
4. Wait for PC commands.
5. PC sends START.
6. Firmware validates sweep settings.
7. Firmware erases flash log region.
8. Firmware enters frequency sweep.
9. For each frequency:
   a. Program AD9833 frequency.
   b. Wait for analog settling.
   c. Sample reference and signal channels with ADC + DMA.
   d. Calculate magnitude and phase.
   e. Send live result to PC.
   f. Store result in W25Q32 flash.
   g. Toggle status LED.
10. Send SWEEP,DONE and final status.
```

This software structure makes the board usable both as a live measurement instrument and as a self-logging measurement device.

## 2. Hardware Description

### 2.1 Hardware Purpose

The hardware is an impedance measurement PCB built around an STM32F303CCT6 microcontroller. The PCB generates a sine-wave excitation signal, applies it to an electrode/load interface, conditions the analog response, samples the resulting signals with the MCU ADC, communicates with a computer over USB-UART, and stores results in external flash memory.

The main hardware blocks are:

```text
USB-C connector
MCP1700 LDO regulator
STM32F303CCT6 microcontroller
AD9833 signal generator
25 MHz oscillator for AD9833
8 MHz crystal for STM32
OPA2140AID precision op-amp analog front end
ADR4533BRZ voltage reference
Electrode connector
CP2102 USB-UART bridge
W25Q32JVSSIQ SPI flash
SWD programming/debug connector
Status LED and test points
```

### 2.2 USB-C Power Input

The board uses a USB-C connector as the external power and USB connection point. The USB-C connector provides `VBUS`, ground, shield, CC pins, USB data pins, and SBU pins.

The CC pins have 5.1 kOhm pull-down resistors. This configures the board as a USB-C sink device, meaning it requests power from the USB-C source. The `VBUS` line provides the input power rail for the board.

The USB data pair is routed toward the CP2102 USB-UART bridge. The STM32 firmware does not use native USB. From the firmware point of view, communication is UART, not USB.

### 2.3 MCP1700 LDO Regulator

The MCP1700 is the board's low-dropout voltage regulator. It receives input from the USB-C power path and generates the regulated supply rail used by the low-voltage electronics.

This is a hardware-only block. The STM32 firmware does not control the regulator. Its job is to provide a stable supply for the MCU, AD9833, analog front end, CP2102-related circuitry, flash memory, and other board components.

### 2.4 STM32F303CCT6 Microcontroller

The STM32F303CCT6 is the central controller of the board. It is responsible for:

```text
running the firmware
controlling the AD9833
sampling analog channels
calculating impedance
communicating with the computer
writing data to SPI flash
driving the status LED
handling debug/programming through SWD
```

The firmware uses these major STM32 peripherals:

| Peripheral | Purpose |
| --- | --- |
| ADC1 | Samples reference and signal channels. |
| DMA1 | Transfers ADC samples into memory. |
| SPI1 | Communicates with AD9833 and W25Q32 flash. |
| USART1 | Communicates with CP2102 USB-UART bridge. |
| GPIO | Controls chip-select/frame-sync pins and status LED. |
| SWD | Programming and debugging. |

The MCU uses an 8 MHz external crystal, `ABM3B-8.000MHZ-B2-T`, connected to PF0/OSC_IN and PF1/OSC_OUT. This clock feeds the STM32 clock tree through `SystemClock_Config()`.

### 2.5 AD9833 Signal Generator

The AD9833 is the signal generator used to produce the sinusoidal excitation waveform. It receives digital control words from the STM32 over SPI and outputs an analog sine wave at `VOUT`.

The AD9833 connections are:

| AD9833 signal | Hardware/software role |
| --- | --- |
| `SDATA` | SPI data from STM32 MOSI. |
| `SCLK` | SPI clock from STM32 SCK. |
| `FSYNC` | Frame sync/chip-select controlled by STM32 PA4. |
| `MCLK` | 25 MHz oscillator input. |
| `VOUT` | Analog sine-wave output. |
| `VDD`, `AGND`, `DGND` | Supply and ground. |
| `CAP/2.5V`, `COMP` | AD9833 support/compensation pins. |

The AD9833 uses the separate `ASE-25.000MHZ-LC-T` 25 MHz oscillator. This clock is important because the firmware uses the same 25 MHz value in the tuning-word calculation. If the hardware oscillator frequency changed, the firmware constant would also need to change.

### 2.6 Analog Front End

The analog front end uses OPA2140AID precision op-amp stages. These op amps condition the excitation/reference and measured response signals so that they are suitable for the STM32 ADC input range.

The analog front end is connected between:

```text
AD9833 output / electrode network -> op-amp conditioning -> STM32 ADC inputs
```

The STM32 samples two channels:

```text
PA0 / ADC1_IN1 -> reference channel
PA1 / ADC1_IN2 -> measured signal channel
```

This two-channel arrangement is essential because impedance measurement requires both amplitude and phase information. A single measured channel alone would not provide enough information to calculate phase relative to the excitation/reference.

### 2.7 Electrode Connector

The electrode connector provides the external measurement interface. It carries the electrode/load connections, labeled as `Electrode1` and `Electrode2` in the schematic.

The unknown impedance is connected at this interface. During a sweep, the AD9833 excitation signal is applied through the analog network, and the response is measured through the analog front end.

In practical terms, this connector is where the actual impedance-under-test is attached.

### 2.8 ADR4533BRZ Voltage Reference

The ADR4533BRZ is a precision voltage reference used by the analog measurement circuitry. Its role is to provide a stable reference or biasing voltage for the analog front end and ADC-related measurement path.

This component improves measurement stability because analog impedance measurements depend strongly on stable voltage references, low noise, and predictable bias points.

The firmware does not directly control the ADR4533BRZ. It is a hardware support component for analog measurement accuracy.

### 2.9 CP2102 USB-UART Bridge

The CP2102 converts USB communication from the computer into UART communication for the STM32.

The signal direction is:

```text
CP2102 TXD -> STM32 USART1 RX / PA10
STM32 USART1 TX / PA9 -> CP2102 RXD
```

The CP2102 connects to the computer through USB. The computer sees a virtual COM port. The STM32 sees ordinary UART data.

The firmware uses 115200 baud, 8 data bits, no parity, 1 stop bit, and no hardware flow control. Sideband pins such as CTS, RTS, DTR, DSR, DCD, and RI are not used by the current firmware protocol.

### 2.10 W25Q32JVSSIQ SPI Flash

The W25Q32JVSSIQ is an external SPI flash memory. It shares the SPI1 bus with the AD9833 but has its own chip-select line.

The flash connections are:

| Flash signal | STM32 mapping |
| --- | --- |
| `/CS` | PB12 / `W25Q32_CS` |
| `CLK` | SPI1 SCK / PA5 |
| `DI(IO0)` | SPI1 MOSI / PA7 |
| `DO(IO1)` | SPI1 MISO / PA6 |
| `/WP(IO2)` | Board-level flash signal, not actively used by firmware. |
| `/HOLD_OR_/RESET(IO3)` | Board-level flash signal, not actively used by firmware. |

The firmware uses the flash to store measurement records from the latest sweep. The flash is not written by the computer directly. The STM32 writes and reads the flash through SPI.

### 2.11 SWD Connector

The SWD connector is used for programming and debugging the STM32. It includes:

```text
SWDIO
SWDCLK
SWO
RESET
VDD
GND
KEY
GND_DETECT
```

In the STM32 pinout:

```text
SWDIO -> PA13
SWDCLK -> PA14
```

This connector is not part of the measurement data path. It is only for firmware loading, debugging, and development.

### 2.12 Status LED And Test Points

The status LED is connected to PB13. The firmware toggles this LED once per measured frequency point. This gives a simple visual indication that the sweep is running.

The schematic also includes test points around important signals and rails. These are useful during hardware bring-up, debugging, and oscilloscope verification. For example, test points can be used to inspect the AD9833 output, analog front-end signals, supply rails, and communication lines.

## 3. Hardware And Software Correlation

### 3.1 Complete System Data Flow

The complete project works as a coordinated hardware/software measurement chain:

```text
PC command
-> CP2102 USB-UART
-> STM32 firmware
-> AD9833 sine-wave generation
-> electrode/load interface
-> OPA2140AID analog front end
-> STM32 ADC + DMA
-> impedance calculation
-> UART result to PC
-> W25Q32 flash storage
```

The computer does not perform the measurement directly. It only configures and commands the board. The STM32 firmware controls the hardware, generates the excitation frequency, samples the analog response, performs the calculation, and stores the result.

### 3.2 Software To Hardware Mapping

| Software function/module | Hardware block controlled or used |
| --- | --- |
| `SystemClock_Config()` | STM32 clock tree using 8 MHz crystal. |
| `MX_ADC1_Init()` | ADC1 channels PA0 and PA1. |
| `MX_SPI1_Init()` | SPI1 bus shared by AD9833 and W25Q32 flash. |
| `MX_USART1_UART_Init()` | USART1 connected to CP2102. |
| `AD9833_SetFrequency()` | AD9833 signal generator. |
| `Imp_MeasureAtFrequency()` | ADC samples from analog front end. |
| `UART_ProcessCommand()` | Computer command input through CP2102. |
| `UART_SendImpedanceData()` | Live result output to computer. |
| `W25Q32_WritePage()` | SPI flash page programming. |
| `FlashLog_WritePoint()` | Stored measurement record in W25Q32. |

### 3.3 SPI Bus Sharing

SPI1 is shared between two devices:

```text
AD9833 signal generator
W25Q32 SPI flash
```

Both devices use the same SPI clock and MOSI line. The flash also uses MISO for reading data back. Device selection is handled by separate control pins:

```text
AD9833 FSYNC -> PA4
W25Q32 CS    -> PB12
```

This means the firmware must ensure only one device is selected during a transaction. The AD9833 driver controls `FSYNC`, while the W25Q32 driver controls `W25Q32_CS`.

### 3.4 UART Communication Correlation

The computer and PCB exchange ASCII messages. The hardware path is:

```text
Computer USB port -> USB-C connector -> CP2102 -> STM32 USART1
```

The software path is:

```text
UART interrupt -> receive buffer -> command parser -> command handler
```

Commands from the computer change sweep settings, start/stop measurements, and request flash data. Replies from the PCB report readiness, status, live measurement data, stored flash records, and errors.

### 3.5 Measurement Correlation

The AD9833 produces the excitation signal. The electrode connector presents the unknown impedance. The OPA2140AID stages condition the signals. ADC1 captures reference and signal waveforms. The software compares the two waveforms to calculate magnitude and phase.

This is why the hardware needs both:

```text
a stable signal generator
a two-channel ADC measurement path
```

The reference channel lets the firmware determine the excitation phase. The signal channel lets the firmware determine the response phase and amplitude. The phase difference between these channels becomes the impedance phase.

### 3.6 Flash Storage Correlation

The flash storage is controlled entirely by firmware. At the start of a sweep, the firmware erases a reserved flash region. At each frequency point, the firmware writes one measurement record.

The computer can ask for flash data, but it does not write to the flash directly. The flow is:

```text
STM32 calculates result -> STM32 writes W25Q32 flash -> PC can request DUMP_FLASH later
```

This gives the project two result paths:

```text
live UART result path
stored flash result path
```

The live path is useful for real-time display. The flash path is useful for keeping a local copy of the sweep.

### 3.7 Power And Reference Correlation

The USB-C connector and MCP1700 provide the board power. The ADR4533BRZ provides precision reference support for the analog measurement path. These blocks do not exchange data with the firmware, but they strongly affect whether the firmware measurements are reliable.

The software assumes stable hardware conditions:

```text
stable supply voltage
stable analog reference
stable oscillator clocks
proper analog signal range
low-noise analog front end
```

If the power or reference is noisy, the ADC data will be noisy. If the AD9833 clock is inaccurate, generated frequencies will be inaccurate. If the analog front end saturates, the impedance calculation will be wrong.

### 3.8 Current Project Behavior Summary

When the user starts a sweep from the PC, the firmware erases the flash log and begins stepping through the configured frequency range. For each frequency, the STM32 programs the AD9833, waits for settling, samples the reference and signal channels, calculates impedance magnitude and phase, sends the live data to the PC, stores a full record in flash, toggles the LED, and moves to the next frequency.

The project is therefore an embedded swept-sine impedance measurement system. Hardware generates and conditions the physical signals. Software controls the sweep, extracts measurement values, communicates with the PC, and stores results.

### 3.9 Practical Use Case

A typical user workflow is:

```text
1. Connect PCB to PC through USB-C.
2. Open serial terminal or PC GUI.
3. Configure sweep start, stop, step, and feedback resistor.
4. Send START.
5. Watch live DATA lines on the PC.
6. Wait for SWEEP,DONE.
7. Use FLASH_STATUS to confirm stored records.
8. Use DUMP_FLASH to retrieve stored records if needed.
```

The resulting data can be plotted as:

```text
magnitude vs frequency
phase vs frequency
real impedance vs frequency
imaginary impedance vs frequency
```

This is the basic form of impedance spectroscopy data.

### 3.10 Final System Summary

The software and hardware are tightly connected. The hardware provides the physical measurement capability: power, clocking, signal generation, analog conditioning, electrodes, ADC input path, communication bridge, and memory. The software turns that hardware into a working instrument by sequencing the sweep, programming the signal generator, acquiring samples, calculating impedance, sending results, and storing data.

In one sentence:

```text
This project is an STM32-controlled swept-sine impedance measurement system that uses an AD9833 for excitation, an OPA2140-based analog front end for signal conditioning, ADC + DMA for waveform capture, firmware-based magnitude/phase calculation, CP2102 USB-UART for PC communication, and W25Q32 SPI flash for stored measurement records.
```
